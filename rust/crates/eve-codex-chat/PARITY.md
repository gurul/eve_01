## Boundaries
None. The app-server is the same external `codex` binary, through eve-codex-computer.

## Differences
- Upstream edit: eve-codex-computer gained an additive "subclass surface" (the underscore members this module uses, and `set_request_handler` in place of overriding `_answer_request`); recorded in its PARITY.md.
- `serde_json` refuses what `json.loads` accepts beyond JSON (`NaN`, `Infinity`) in `.codex-global-state.json`: such a file is "Could not read saved Codex folders." where Python would read it.
- Callbacks return `anyhow::Result<()>`: an error that is a `CodexError::Unavailable`/`Timeout` takes the `except (TimeoutError, CodexUnavailable)` branch, any other error ends the turn job and is returned by the next `send`/`wait_turn` (Python re-raises it from `await self._turn_job`), carried as `CodexError::Py` with class `Exception`.
- A turn job whose done future is dropped (never in practice: only `close` replaces it, after cancelling the job) ends as `CodexError::Cancelled`.
