## Boundaries
None. The live ears' WebSocket is tokio-tungstenite and the speech POST is reqwest; both are behind seams (`RealtimeConnect`, `speech_url`, `NotesSdk`) so the tests run with no network.

## Differences
- Python's speech pump ran `speak_stream` to its end on an executor thread even after a barge-in cancelled the reader; the Rust speech thread does the same (its sends to a gone reader are ignored), so the spend line is still written for speech that was made in full.
- A `serde_json` parse of the hello cannot read bare `NaN`/`Infinity`, which `json.loads` accepts; such a hello is treated as no hello ("Only eve's owner can call."). A real phone never sends them.
- The realtime connection carries only the `Authorization` header, not the openai SDK's `User-Agent`/`X-Stainless-*` headers.
- `Ears::discard` is a required trait method; Python's call checked `hasattr(ears, "discard")`. Every `Ears` has it.
- Python's `ImportError` branch in `make_voice` (the openai SDK missing, so calls off) has no Rust counterpart: the client is always linked.
- Every I/O error on the call's socket is `Closed`, as Python's `ConnectionError`/`IncompleteReadError` were; an OS error that Python would have let escape (none seen in practice) ends the call the same quiet way.
- `NOTES_GRACE_SECS`, `AUTH_SECS`, `QUIET_SECS` and `MAX_CALL_SECS` are read from settable fields (`PhoneNotes::set_grace_secs`, `PhoneCalls::limits`, `Call::with_limits`) whose defaults are the constants, where Python's tests patched the module.
- Brain capabilities Python discovered by introspection (`answer_context`, `call=`, `chat_ready`) are trait methods a brain overrides.
- `Call::run` returning "eve's chat isn't running" also stops the reader and the ears it started; Python returned before its `try`, so its `finally` never ran and both were left running (a leak, never visible on the phone, which is told the call ended either way).
- `PhoneNotes::stop` called in the moment after the write-up let go of its session but before it finished texting returns `ok` with `path: null` and zero counts; Python raised `AttributeError` reading `None.state` there.
- `_watch`'s "the phone's notes broke" warning has no counterpart: `eve_notes::RoomNotes`'s session task returns nothing to fail with (its errors are logged inside eve-notes), so the write-up always follows.
