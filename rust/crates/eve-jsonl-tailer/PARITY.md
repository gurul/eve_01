## Differences
- A lone UTF-16 surrogate (from a `\udXXX` escape, `surrogatepass` UTF-8, or UTF-16/32 input) is a valid Python `str` character but cannot be in a Rust `String`; it becomes U+FFFD. The record is still parsed and counted; only an emitted assistant text differs in that character.
- Integers are `i64`: a token count past `i64` saturates (Python's are unbounded). Whether `int * float` would raise `OverflowError` is still decided from the exact value, so the same records are skipped.
- A transcript path that is not valid UTF-8 is skipped by the initial sweep with a debug line (Python processes it under its surrogate-escaped name). The watcher reports such a path as an error, as watchfiles does.
- The JSON depth limit is fixed at 9995, CPython's limit from the `asyncio.to_thread` worker the tailer runs on; CPython's real limit shifts by a few levels with the caller's C call depth.
- watchfiles runs its batching loop on a worker thread; here it is a task on the tokio timer with the same step, debounce and timeout. `WATCHFILES_DEBUG` output prints the same notify `Debug` text; the `%d changes detected: %s` debug line prints a Rust `Debug` of the set rather than a Python repr.
- Python's `log.exception` adds a traceback; the Rust log line carries the error chain instead.
- Off Unix, `localtime` is read through chrono's `Local` rather than `localtime_r`.
