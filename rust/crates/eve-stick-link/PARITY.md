## Differences
- `latest_address`: Python raises `AttributeError` out of the function when a line of the reply is valid JSON but not an object (e.g. `5`), and lets `http.client.HTTPException` (an `IncompleteRead` while reading) escape; Rust skips such a line and reads any failed request as "". The phone does the same.
- JSON that Python's `json` accepts beyond RFC 8259 (`NaN`, `Infinity`, lone surrogate escapes, nesting deeper than 128) is unreadable to serde_json: a token file or rendezvous line like that counts as damaged. So is one where the field read (`token`, `event`, `message`) holds an out-of-range number such as `1e400`, even if a later duplicate of that key would be valid. eve never writes one.
- A redirect to `ftp://` is refused (urllib would follow it over FTP).
- The 10 s timeout covers the whole request in Rust; urllib applies it to each socket operation. Rust sends no `User-Agent` (urllib sends `Python-urllib/3.x`). The `TransportError` type names approximate the Python exception that would have been logged.
