## Boundaries
- **Speaker**: sounddevice's `RawOutputStream(samplerate=24000, channels=1, dtype="int16")` becomes cpal on the default output device (`src/audio_out.rs`). PortAudio converts the format itself; cpal does not, and asking CoreAudio for 24 kHz would change the device's rate under every other app, so the stream opens at the device's default format: int16 to float as PortAudio's `Int16_To_Float32` (`x / 32768`), linear resampling to the device rate, the sample copied to every channel. A write blocks while more than `BUFFER_SECS` (0.1 s) waits, as PortAudio's blocking write does once its buffer is full; the stop lets what was written play out, as `Pa_StopStream` does. The stream is opened and used on the player thread (cpal streams are not `Send` everywhere).
- **Microphone**: through eve-ears' `AudioBackend` (cpal), whose own boundary is recorded in eve-ears' PARITY.md.

## Differences
- `QUIET_SECS` and `PING_SECS` are read from settable values (`DeskCalls::limits`, `DeskCalls::set_ping_secs`) whose defaults are the constants, where the Python tests patched the modules.
- A speaker that fails to play (a `BoardSpeaker` send error) surfaces to the call as `Closed` (its reader stops, as the Python reader task died on the exception), with a `desk call: the speaker failed (...)` warning the Python did not log.
- A speaker that fails a flush: Python's exception left `Call.interrupt` and `Call.run` at once, so the call ended and logged `desk call: ended (?)`. `CallSocket` can only return `Closed`, which the call suppresses there, so the link closes itself and is marked `failed`: the call ends at its next read (after the rest of that press's start), and the desk logs the end as `ended (?)`, with the warning above.
- `desk call: phase hook failed` carries the error text instead of a traceback.
- Phase hooks run one at a time in order (a lock held across the hook), and ring lines are sent one at a time in the order the ring changed (a lock held across the board send). In Python a hook or a send could overlap another at an await, but each started in the order of the change on the single loop thread; on the multi-threaded runtime a later one could otherwise start first and leave the follower or the board on a stale state.
- Microphone blocks go into the call's inbox from the audio thread directly. Python hopped through `loop.call_soon_threadsafe`, so a block still waiting for the loop when the button came up landed after `done` and was dropped (at most a block or two of the press's last 50 ms); here it lands before `done` and is part of the press.
- The Mac speaker's output buffer (at most ~0.2 s) is not dropped by a flush, as PortAudio's own buffer was not; samples are not bit-identical to PortAudio's when the device runs at another rate (different resampler).
- The default `BoardSpeaker` clock is a process-relative monotonic clock; only differences of it are used.
