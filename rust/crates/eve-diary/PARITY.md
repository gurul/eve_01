## Differences
- `take`, `keep` and `reflect` return `Err` for what Python lets escape them: a frame that cannot be encoded, a file that cannot be read or written, a reply whose shape makes Python's built-ins raise (a numeric `tags`, an unreadable `p`, an infinite number), and `DiaryCancelled` for a queued call dropped by `stop()` (Python's `CancelledError`). A panic inside a client call counts as a failed call; a panic inside `on_written` / `on_thought` is logged like Python's caught exception. `take` needs the taker in an `Arc` so it can spawn the dreams pass.
- The dreams pass is claimed when `take` schedules it rather than when the task first runs, so two takes in a row can never schedule two passes on a multi-threaded runtime; the flag is released on every path where Python would not have set it, so the observable behaviour is Python's.
- A memory line whose fields have the wrong JSON types (a string `ts`, a list `thought`) is skipped as malformed; Python loads it and fails later when it uses it. A `null` in a defaulted field reads as the default. A non-string `day` in `reflection.json` is kept as its `str()` and written back as a string. A `reflection.json` that is not an object errs from `load` as Python's AttributeError does.
- JSON is parsed by serde_json: Python's `NaN`/`Infinity` literals and integers too large for a float are rejected (as an unparseable reply, or a malformed memory line), and decode error messages differ in wording (the class name `JSONDecodeError` is the same).
- `str.isprintable()` in the `%r` of the "looked closer" log line is approximated by the common non-printable ranges.
