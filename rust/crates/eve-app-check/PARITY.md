## Boundaries
- The browser is Chromium driven over the Chrome DevTools Protocol (`src/cdp.rs`, on `tokio-tungstenite`), not Playwright: no Python, no Node, no subprocess other than Chromium itself. It is the Chromium Playwright installs (`chromium_headless_shell-<rev>` under `PLAYWRIGHT_BROWSERS_PATH` or `~/Library/Caches/ms-playwright`, newest revision first, then Playwright's full Chromium, then an installed Chrome or Chromium), started with Playwright's own default switches and `CHROMIUM_ARGS`. A hand-written client rather than `chromiumoxide`: the check needs flattened sessions with request interception, bindings, crash events and bounded calls on a page that may hang, and a page left behind by a stopped check must close without an await (`Context`'s `Drop`).
- What Playwright provides inside the page is done by injected scripts, as Playwright does it: `expose_function` is a `Runtime.addBinding` plus a promise per call (`BRIDGE_JS`); `route_web_socket` replaces `window.WebSocket` with one that reports itself to the checker and is closed there, so no socket is ever opened; `page.clock` is `CLOCK_JS` (timers and `Date` on a clock that keeps real time until `fast_forward` jumps it, firing each due timer once and throwing the first error a timer threw).

## Differences
- No Chromium found is a skip that says `Chromium is not installed` (Python, without Playwright: `Playwright is not installed`); `CheckOptions::executable` names the Chromium to use.
- Playwright picks the browser revision that matches its own version; here the newest installed revision is used.
- Saved data that is not JSON (an app calling the stand-in's hidden function with junk) reads as no data, where Python's `json.loads` would raise out of `check_app`.
- A failure's class name (`the check could not run (…)`, `the journeys could not run (…)`) is the page error's kind (`Error`, `TimeoutError`, `TargetClosedError`) or `Error`, not a Python exception class name.
- Chromium runs with site isolation off, so a cross-site iframe stays in the page's process and its requests go through the page's router (Playwright instead follows the iframe's own process); what is fenced and reported is the same.
